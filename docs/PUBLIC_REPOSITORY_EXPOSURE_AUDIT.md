# Public repository exposure and workflow safety audit

Date: 2026-11-23  
Scope: the current `main` tree and its GitHub Actions workflows, inspected from the research branch without changing `main`.

## Executive finding

The repository is currently **public** and is a **fork**. It contains research outputs and model-derived betting analysis that the owner has described as personal-use work. Treat the current contents, commit history, Actions logs, and any artifacts from this repository as publicly accessible.

A public fork cannot have its visibility changed independently. GitHub documents that public forks remain public even if the upstream repository becomes private. The GitHub repository metadata currently reports this fork at 647 KB with zero child forks; that is within the documented size/no-child-fork conditions for the manual Leave network detachment option. This makes detachment into a standalone repository a plausible route, but it is a permanent network change and must be performed deliberately. A separate new private repository is the alternative. See GitHub's fork and visibility documentation before attempting migration.

## Content and secret scan limits

The tree paths and representative data headers/rows were inspected. No obvious personal account identifiers, access tokens, passwords, private keys, or credential-file paths were identified in that limited review.

This was **not** a byte-for-byte secret scan of every historical Git object, every CSV cell, every Actions log, or every artifact. Do not interpret it as proof that the entire repository history is free of secrets or personal information. If a credential is ever found in public history, rotate it first; deleting the current file alone does not revoke it.

## Workflow exposure paths found on main

### `.github/workflows/collect-jra.yml`

- Manual dispatch.
- `contents: read`.
- Produces SQLite, train/validation/test CSVs, race/source audits, summary, and fetch log.
- The original artifact step used `if: always()` and 30-day retention.

In a public repository, a successful run could publish the generated database and split datasets to everyone with repository read access. A failed run could also publish partial outputs/logs. The research branch now adds a private-repository visibility gate before data collection and changes artifact publication to success-only.

### `.github/workflows/fetch-current-odds.yml`

- Originally triggered by both pushes to selected main paths and manual dispatch.
- Uses `contents: write`.
- Originally uploaded the entire `results/live_odds/` directory and attempted to commit that directory even when earlier steps failed.
- The paired collection script has a hard-coded race ID for the 2026-10-18 Shuka Sho and fetches from a public third-party odds endpoint. Its former "today/current" workflow naming was misleading after that race date.

The research branch now removes the automatic push trigger, adds a private-repository gate, publishes only the two JSON files generated by the script, and commits only those two files after successful collection. Git commit/push errors are no longer silently ignored. Manual use still requires checking that the configured race ID is the intended target.

### New JRA PDF acquisition workflow

The research branch also requires private repository visibility before restoring the private manifest or downloading PDFs. Artifact publication occurs only after successful download and layout audit. The workflow has not been run.

## Required boundary before further data collection

1. Do not run the historical-data, odds-capture, or PDF-acquisition workflows while this repository is public.
2. Do not merge this draft PR merely to enable PDF acquisition.
3. For personal-use data, create a separate private repository and migrate only reviewed source code/configuration, keeping private manifests, datasets, predictions, odds, model binaries, and artifacts out of public Git history.
4. Because this repository is a public fork, it cannot be toggled to private independently. GitHub metadata currently reports 647 KB and zero child forks, so the manual Leave network option appears to meet its documented size and child-fork eligibility conditions. Detachment is permanent; alternatively create a new private repository and migrate reviewed source code.
5. Before migrating or changing visibility, review existing public commits, forks, clones, and any previously published Actions artifacts. A visibility change cannot retract copies already made by others.
6. Confirm third-party data licensing/terms before retaining or republishing downloaded source data.
